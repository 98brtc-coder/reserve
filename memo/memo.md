# 1. QR 평가 제한 문제 파악 및 대안 검토

**2026-10-20 작성**

## 문제

예비군은 입소 시 **카메라 차단 앱**이 적용된다. 보안 정책이므로 평가를 위해
풀어 줄 수 없다. 따라서 **QR 코드를 쓸 수 없다.**

그렇다고 종이 평가지로 돌아가면 채점과 집계가 전부 수작업이 된다.
조별 평균을 내서 우수 조를 뽑아야 하는데, 수백 명분을 당일에 처리할 수 없다.

필요한 것은 **카메라를 거치지 않고 휴대폰에 주소를 전달하는 방법**이었다.

## 검토한 대안

| 대안 | 판단 | 사유 |
|---|---|---|
| QR 코드 | **불가** | 카메라가 차단됨. 정책상 해제 불가 |
| 주소 직접 입력 | 기각 | 수백 명이 긴 주소를 타자. 오타 처리가 더 큰 부담 |
| 단축 주소 | 기각 | 여전히 타자해야 하고, 단축 서비스가 중단되면 전체가 멈춤 |
| 문자 · 카카오 발송 | 기각 | 연락처를 수집해야 함. 개인정보 부담이 평가 목적에 비해 과도 |
| 부대 와이파이 접속 화면 | 기각 | 망 설비를 건드려야 하고 통제 범위를 벗어남 |
| **NFC 카드** | **채택** | 카메라와 무관. 태그 한 번으로 열림. 카드 재사용 가능 |

## NFC 를 고른 이유

- **카메라를 전혀 쓰지 않는다** — 차단 앱과 무관하게 동작한다
- **예비군이 할 일이 태그 한 번**이다 — 주소를 외우거나 입력할 필요가 없다
- **카드를 회차마다 재사용**한다 — 소모품이 아니다
- 아이폰 XS 이상은 **화면만 켜져 있으면** 자동 인식된다

## 지금 구축된 모습

```
 카드 태그            카드에는 '주소 한 줄'만 기록되어 있다
      │
      ▼
 부대 전용 페이지      GitHub Pages (무료 · 상시)
      │               예비군이 조·번을 한 번 고른다
      ▼
 배너 4개             안보교육 / 전투부상자처치 / 전시동원절차 / 설문
      │
      ▼
 구글폼               번호가 미리 채워진 상태로 열린다
      │
      ▼
 응답 스프레드시트      조별 평균 → 우수 조 자동 산출
```

### 카드에 번호를 넣지 않았다

가장 중요한 결정이다. 카드 500장이 **전부 똑같다.**

| | 번호를 넣는 방식 | 지금 방식 |
|---|---|---|
| 카드 종류 | 500종 (1-1 ~ 50-10) | **1종** |
| 조 편성 변경 시 | 500장 다시 기록 | **그대로 사용** |
| 카드 분실·혼동 | 그 번호를 쓸 수 없음 | 아무 카드나 사용 가능 |
| 번호 지정 | 카드가 결정 | 첫 화면에서 본인이 선택 |

번호는 예비군이 첫 화면에서 한 번 고르고, 그 뒤로는 폼에 **자동 입력**된다.
카드와 번호를 맞춰 배부할 필요가 없으므로 입소 절차가 단순해진다.

> 조별 카드를 따로 쓰고 싶으면 주소 뒤에 `?g=3` 을 붙여 기록하면 된다.
> 지금은 쓰지 않는다 — 카드를 1종으로 두는 이점이 더 크다고 판단했다.

### 주소를 깃헙 페이지에 둔 이유

구글 앱스스크립트로 첫 화면까지 만들 수도 있었지만, **동시 접속**이 문제였다.
수백 명이 한꺼번에 태그하면 앱스스크립트 쪽이 먼저 막힌다.

그래서 **첫 화면은 깃헙이 내려주고**(정적 파일, 동시 접속 제한 없음),
앱스스크립트는 열림·닫힘 상태 확인과 집계만 맡게 했다.
서버가 늦어도 화면은 즉시 뜬다.

## 확인된 제약 — 카드 구매·운용 시 주의

| 제약 | 내용 |
|---|---|
| 칩 종류 | **NTAG213 / 215 / 216 만 가능.** Mifare Classic 은 아이폰에서 읽히지 않는다 |
| 금속 | 철제 책상·캐비닛에 붙이면 인식되지 않는다. 카드로 배부한다 |
| 구형 아이폰 | 7 ~ X 는 제어센터에 `NFC 태그 리더` 를 추가해 실행해야 한다 |
| 안드로이드 | `설정 → 연결 → NFC` 가 켜져 있어야 한다 |
| 카드 잠금 | 되돌릴 수 없다. 주소가 확정된 뒤에만 잠근다 |

사무실에 흔한 출입증 계열이 대부분 Mifare Classic 이다. **`NTAG` 로 명시된
카드를 구매해야 한다.** 이 지점에서 실패하는 경우가 가장 많다.

## 대비책

카드가 인식되지 않는 경우를 대비해 **주소를 카드 뒷면에 인쇄**한다.
NFC 가 안 되는 구형 기종이나 카드 불량일 때 직접 입력으로 넘어갈 수 있다.

```
휴대폰 뒷면 윗부분에 카드를 대면 평가·설문 화면이 열립니다.
열리지 않으면: 설정에서 NFC 켜기 (아이폰은 화면만 켜면 됩니다)
그래도 안 되면 주소 직접 입력: <부대 주소>
```

## 결과

카메라 차단 상태에서 **QR 없이** 평가·설문이 동작한다.
예비군이 하는 일은 **카드 태그 → 조·번 선택 한 번 → 배너 누르기** 뿐이다.

# 2. NFC 카드 활용 평가 체계 구상

**2026-10-21 작성**

1번에서 **NFC 로 주소를 전달한다**는 것까지 정했다. 이 단계에서는 그 주소 뒤에
무엇을 둘지, 즉 **평가 체계 전체의 골격**을 정했다.

## 체계가 해야 할 일

| 요구 | 비고 |
|---|---|
| 평가 3과목 응시 | 안보교육 / 전투부상자처치 / 전시동원절차 |
| 자동 채점 | 당일에 결과가 나와야 한다. 수작업 채점은 불가 |
| 조별 평균으로 **우수 조** 선정 | 개인 시상이 아니라 조 단위 시상이다 |
| 무기명 설문 | 평가와 분리. 솔직한 응답을 받아야 한다 |
| 교관이 **열고 닫는다** | 통제 없이 열어 두면 무분별하게 제출된다 |

## 구상 1 — 사람을 무엇으로 식별할까

**`조-번` (m-n) 으로 정했다.** 이름·군번·연락처를 받지 않는다.

| 식별 방법 | 판단 |
|---|---|
| 이름 | 기각 — 동명이인. 개인정보를 받을 이유가 없다 |
| 군번 | 기각 — 입력이 길고 오타가 많다. 민감정보 |
| 연락처 | 기각 — 수집 근거가 없다 |
| **조-번** | **채택** — 당일 편성이면 충분하다. 시상 단위와 일치한다 |

시상 단위가 **조**이므로 개인을 특정할 필요가 애초에 없었다.
`3-7` 이면 3조의 득점에 더하는 것으로 충분하다.

훈련이 끝나면 조 편성 자체가 의미를 잃으므로, **남는 자료에 개인정보가 없다.**
이 점이 결정적이었다.

## 구상 2 — 평가지를 새로 만들지 않는다

구글폼 **퀴즈 기능**을 그대로 쓴다. 문항·정답·배점을 넣으면 **자동 채점**되고
응답이 스프레드시트로 쌓인다.

평가 화면을 직접 만들면 문항 편집기·채점·저장을 전부 만들어야 한다.
그 부분은 이미 있는 것을 쓰고, **없는 것만 만들기로** 했다.

| 구글폼이 해 주는 것 | 우리가 만들 것 |
|---|---|
| 문항 표시 · 답안 수집 | 첫 화면 (어느 폼으로 보낼지) |
| 자동 채점 · 점수 기록 | 조별 집계 · 우수 조 산출 |
| 응답 수락 열기/닫기 | 교관 화면 (언제 누가 열지) |
| 응답을 시트로 저장 | 번호 자동 입력 · 중복 처리 |

## 구상 3 — 세 겹으로 나눈다

한 군데에 몰면 **동시 접속**에서 막힌다. 역할을 셋으로 쪼갰다.

```
① NFC 카드          주소 한 줄.          변하지 않는다
       │
       ▼
② 첫 화면           깃헙 페이지(정적).   동시 접속 제한 없음
   (어느 폼으로)     수백 명이 한꺼번에 태그해도 즉시 뜬다
       │
       ▼
③ 앱스스크립트       열림·닫힘 상태 확인, 집계.
   (판단과 계산)      동시 처리 한계가 있으므로 꼭 필요한 일만 맡긴다
```

**원칙: 화면은 서버를 기다리지 않는다.** 상태 조회가 늦어도 첫 화면은 먼저
뜨고, 상태를 받으면 배너가 갱신된다. 수백 명이 동시에 들어오는 상황에서
"흰 화면"이 나오면 안 된다.

## 구상 4 — 무엇으로 실제로 막을까

열고 닫기를 화면에서만 처리하면, **주소를 아는 사람은 그냥 들어간다.**
그래서 차단 지점을 두 겹으로 나눴다.

| 겹 | 수단 | 성격 |
|---|---|---|
| 실제 차단 | 구글폼의 **응답 수락** 끄기 | 주소를 직접 열어도 제출 불가 |
| 안내 | 첫 화면 배너를 `마감`·`대기` 로 표시 | 헛걸음을 줄인다 |

**진짜 잠금은 구글폼 쪽**이고, 화면 표시는 안내다. 이 구분을 처음에 정해 두지
않으면 "닫았는데 들어가졌다" 는 사고가 난다.

## 구상 5 — 규모는 방어적으로

입소 인원은 회차마다 다르다. **50개 조 × 10명 = 500명**까지 동작하게 잡았다.

- 실제 참가가 328명이어도 그대로 쓴다. 빈 조는 집계에서 빠진다
- 조 평균은 **실제 응시인원**으로 나눈다. 조기 퇴소자 때문에 불리해지지 않는다
- 인원이 늘어도 설정값만 바꾸면 된다

## 구상 6 — 하루 단위로 끊는다

예비군은 날마다 다른 사람이 들어오고, **같은 사람이 다른 조·번**으로 들어올
수도 있다. 그래서 모든 것을 **날짜로 끊기로** 했다.

| 대상 | 하루가 지나면 |
|---|---|
| 번호 등록 | 비워진다. 어제 `3-7` 이던 사람이 오늘 `12-4` 로 들어와도 된다 |
| 평가·설문 개방 | 전부 닫힌 상태로 돌아간다 |
| 집계 | 그 날짜 기준으로 낸다. 과거 날짜는 따로 조회한다 |

**기본값은 전부 닫힘**이다. 열어야 열리는 것이지, 닫아야 닫히는 것이 아니다.
교관이 깜빡해도 다음 회차가 열린 채로 시작하지 않는다.

## 이 단계에서 정하지 않고 넘긴 것

구상 단계에서 결론을 미룬 것들이다. 뒤 단계에서 정했다.

| 보류한 것 | 어디서 정했는가 |
|---|---|
| 평가지를 A안·B안으로 나눌지 | 14단계 — 조별 `ABBA` 배정으로 결정 |
| 같은 번호가 여러 번 내면 어떻게 할지 | 17단계 — **처음 제출만** 인정 |
| 번호를 카드에 박을지 | 19단계 — **보류**. 카드 1종 유지 |
| 조별로 따로 열지 | 16단계 — 과목 × 조 단위로 개폐 |

## 결과

골격이 이렇게 정해졌다.

```
카드(주소) → 첫 화면(조·번 선택) → 구글폼(자동 채점) → 시트(조별 집계)
                    ▲                      ▲
                    └── 교관 화면 ──────────┘
                        (열고 닫기 · 현황 · 우수 조)
```

개인정보를 받지 않고, 평가지를 새로 만들지 않고, 동시 접속에 막히지 않는 구조다.
