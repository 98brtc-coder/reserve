# 예비군 평가 · 설문 시스템

NFC 카드를 휴대폰에 태그하면 부대 전용 페이지가 열리고, 거기서 **평가**와 **설문**
구글폼으로 연결됩니다. 카메라 차단 상태에서도 QR 없이 동작합니다.

```
 NFC 카드 태그
      │
      ▼
 부대 전용 페이지          배너 4개
 (index.html)   ──┬──▶ [안보교육]       ──▶ 구글폼(퀴즈) ─┐
                  ├──▶ [전투부상자처치] ──▶ 구글폼(퀴즈) ─┼─▶ 응답 스프레드시트
                  ├──▶ [전시동원절차]   ──▶ 구글폼(퀴즈) ─┘    (탭 3개)
                  └──▶ [설문 참여]      ──▶ 구글폼(무기명) ─▶ 폼 요약 그래프
      │                                                          │
      ▼                                                          ▼
 관리자 페이지 (admin.html) ◀── Apps Script ──── 과목별 집계 + 종합 순위
   · 과목별 / 전체 열기·닫기     (Code.gs)        (득점률 평균)
   · 종합 순위 → 우수 조
```

## 폴더 구성

| 경로 | 설명 |
|---|---|
| `docs/index.html` | 예비군이 보는 첫 화면 (평가 · 설문 배너) |
| `docs/admin.html` | 교관용 관리자 화면 (현황판 · 개폐 버튼) |
| `docs/config.js` | **부대별 설정 파일 — 여기만 수정** |
| `docs/styles.css`, `common.js`, `landing.js`, `admin.js` | 화면 구성 파일 (수정 불필요) |
| `apps-script/Code.gs` | 구글 시트에 붙여넣는 백엔드 코드 |
| `memo/memo.md` | 구축 경위 메모 — 단계별로 무엇을 왜 그렇게 했는지 |

# 설치 (1회, 약 30분)

## 1단계 · 구글폼 만들기 (평가 3과목 + 설문 1개 = 총 4개)

### 평가용 폼 — **안보교육 / 전투부상자처치 / 전시동원절차** 각각 1개씩

1. [forms.google.com](https://forms.google.com) 에서 새 폼 생성 → 제목에 **과목명을 그대로** 넣으십시오
   (예: `안보교육 평가`). 과목명이 들어가면 응답 시트를 자동으로 찾아줍니다.
2. **설정 → 퀴즈로 만들기** 켜기 (자동 채점되어 `점수` 열이 생기고 만점도 자동 인식됩니다)
3. **첫 번째 질문**을 아래와 같이 만듭니다.
   - 질문: `본인 번호`
   - 유형: **단답형** / **필수** 켜기
   - 설명: `번호가 미리 입력되어 있습니다. 비어 있으면 조-번 형식으로 입력하십시오. 예) 3-7`
   - ⚠ **응답 확인(정규식)은 넣지 마십시오.** 폼 동기화 오류를 일으킨 사례가 있습니다.
4. 평가 문항을 추가하고 각 문항의 **답안 및 배점**을 지정합니다.
5. 우측 상단 **`게시(Publish)`** 버튼을 눌러 **한 번 게시**합니다.
   게시하지 않으면 열기/닫기가 동작하지 않습니다.
6. 위 1~5를 **3과목 모두** 반복합니다.

> `응답 횟수 1회로 제한`은 **끄는 것을 권장**합니다. 구글 로그인을 강제하게 되어
> 예비군들이 막힙니다. 중복 제출은 시스템이 *처음 제출만* 인정하므로 문제없습니다.

### 설문용 폼 (1개)
1. 새 폼 생성 → **이메일 수집 끄기**, 번호 질문 **없음** (무기명)
2. 우측 상단 **`게시`** 버튼 클릭
3. 실시간 결과는 폼의 **응답 → 요약** 탭에서 바로 확인됩니다

## 2단계 · 응답을 스프레드시트 하나로 모으기

**3과목 응답을 반드시 같은 스프레드시트에 모으십시오.** 따로 만들면 집계가 되지 않습니다.

1. **안보교육** 폼 → `응답 → 스프레드시트에 연결 → 새 스프레드시트 만들기`
   → 이름 예: `예비군 평가 관리`
2. **전투부상자처치** 폼 → `응답 → 스프레드시트에 연결 → **기존 스프레드시트 선택**`
   → 방금 만든 `예비군 평가 관리` 선택
3. **전시동원절차** 폼도 같은 방식으로 기존 스프레드시트에 연결
4. 결과적으로 스프레드시트에 응답 탭이 **3개** 생깁니다

> 설문 폼은 연결하지 않아도 됩니다. 집계가 필요 없습니다.

## 3단계 · Apps Script 설치

1. 방금 만든 스프레드시트에서 **확장 프로그램 → Apps Script**
2. 기본 코드를 모두 지우고 `apps-script/Code.gs` 내용을 붙여넣고 저장
3. 상단 함수 목록에서 **`setup`** 선택 → **실행** → 권한 승인
   (⚠ "이 앱은 확인되지 않았습니다" 화면이 나오면
   `고급 → 안전하지 않은 페이지로 이동` 을 누릅니다. 본인이 만든 스크립트입니다.)
4. 스프레드시트에 **`설정`** 과 **`과목`** 두 탭이 생깁니다.

**`설정` 탭** — 부대 공통 항목

| 항목 | 예시 값 | 설명 |
|---|---|---|
| 부대명 | `서산 과학화 예비군훈련대` | 첫 화면 제목 |
| 관리자PIN | `74125` | **반드시 변경.** 교관들끼리 공유 |
| 설문폼_편집링크 | `https://docs.google.com/forms/d/2XyZ.../edit` | 설문 폼의 **편집** 주소 |
| 조개수 | `10` | 전체 조 수 (m) |
| 조별인원 | `10` | 조당 인원 (n) |
| 평가마감안내 | (기본값 사용) | 마감 시 화면에 뜨는 문구 |

**`과목` 탭** — 평가 과목 3개 (기본으로 3행이 채워져 있습니다)

| 과목명 | 폼_편집링크 | 만점 | 개방 | 개방조 | B안_폼_편집링크 |
|---|---|---|---|---|---|
| 안보교육 | `.../forms/d/1AbC.../edit` | *자동* | 아니오 | 전체 | (B안 쓸 때만) |
| 전투부상자처치 | `.../forms/d/1DeF.../edit` | *자동* | 아니오 | 전체 | (B안 쓸 때만) |
| 전시동원절차 | `.../forms/d/1GhI.../edit` | *자동* | 아니오 | 전체 | (B안 쓸 때만) |

나머지 열(`폼_응시링크`, `폼_프리필링크`, `응답시트`, `B안_…`)은 **비워 두십시오** — 자동으로 채워집니다.
**`개방조`는 과목마다 따로 관리됩니다.** 비워 두면 `설정` 시트의 `개방조` 값을 기본값으로 씁니다.

- **`폼_편집링크`만 채우면 됩니다.** 응시링크는 자동으로 채워집니다
- **`응답시트`**: 과목명이 시트 이름에 들어 있으면 비워둬도 자동으로 찾습니다.
  못 찾는다는 경고가 뜨면 그때 시트 이름을 정확히 적으십시오
- **`만점`**: 퀴즈형 폼이면 자동 인식됩니다. 인식이 안 되면 숫자를 직접 적으십시오.
  **만점이 없으면 그 과목은 종합 순위에서 제외됩니다**
- **`개방`**: 관리자 화면에서 바뀌므로 그대로 두십시오

> **편집링크 vs 응시링크**: 주소에 `/d/e/`가 들어간 것은 *응시용* 링크입니다.
> `/d/<아이디>/edit` 형태의 **편집 링크**를 넣어야 열기·닫기가 동작합니다.

5. 조 인원이 조마다 다르면 **`명단`** 이라는 탭을 만들고 A1에 `번호`,
   A2부터 `1-1`, `1-2`, … 를 모두 적습니다. 명단 탭이 있으면 그것이 우선합니다.

6. **배포**
   - 우측 상단 **배포 → 새 배포 → 유형 선택(톱니) → 웹 앱**
   - 설명: `예비군 평가 v1`
   - **다음 사용자 인증 정보로 실행: 나**
   - **액세스 권한이 있는 사용자: 모든 사용자** ← 중요
   - 배포 → 받은 **웹 앱 URL** (`https://script.google.com/macros/s/..../exec`) 복사

## 4단계 · 웹페이지 올리기 (GitHub Pages, 무료)

1. `docs/config.js` 를 열어 두 곳을 채웁니다.
   ```js
   unitName: "제○○보병사단 예비군훈련대",
   apiUrl:   "https://script.google.com/macros/s/..../exec",
   ```
   (평가·설문 링크는 설정 시트에서 자동으로 가져오므로 비워 둡니다.)

2. [github.com](https://github.com) 에서 새 저장소 생성 (예: `reserve`, **Public**)
   ※ 현재 주소: `https://98brtc-coder.github.io/reserve/`
3. 이 폴더의 파일들을 업로드 (`Add file → Upload files` 로 폴더째 끌어다 놓기)
4. 저장소 **Settings → Pages** → Source: `Deploy from a branch`,
   Branch: `main` / 폴더: **`/docs`** → Save
5. 1~2분 뒤 주소가 나옵니다: `https://<아이디>.github.io/reserve/`
   → 이 주소가 **NFC 카드에 넣을 주소**입니다. 휴대폰으로 먼저 열어 확인하십시오.

> 사내망·보안 정책상 GitHub 가 어렵다면 Cloudflare Pages, Netlify Drop 등
> 정적 호스팅 어디든 `docs` 폴더만 올리면 동일하게 동작합니다.

## 5단계 · NFC 카드 제작

### 카드 선택 — 여기서 실패하는 경우가 가장 많습니다
- **필요한 것은 NFC (13.56MHz) 카드**이며, 칩은 **NTAG213 / NTAG215 / NTAG216** 이어야 합니다.
- **Mifare Classic 카드는 아이폰에서 읽히지 않습니다.** 사무실에 흔한 출입증
  계열이 대부분 Mifare Classic 이므로, 반드시 `NTAG` 로 명시된 카드를 구매하십시오.
- 용량: NTAG213(144바이트)로도 위 주소는 충분합니다. 주소가 길면 NTAG215/216.
- 금속 표면(철제 책상, 캐비닛)에 붙이면 인식이 안 됩니다. 카드 형태로 배부하십시오.

### 기록 방법
1. 휴대폰에 **NFC Tools** (또는 NXP TagWriter) 설치
2. `쓰기 → 레코드 추가 → **URL/URI**` → 4단계에서 받은 주소 입력
3. `쓰기` 를 누르고 카드를 태그 → 여러 장을 연속으로 쓸 수 있습니다
4. 배포 전 **다른 휴대폰(아이폰/안드로이드 각 1대)으로 반드시 테스트**
5. 주소가 확정된 뒤에만 앱의 **잠금(Lock)** 기능을 사용하십시오.
   잠그면 **되돌릴 수 없습니다.** 처음 몇 장은 잠그지 않고 운용을 권장합니다.

### 예비군 안내 문구 (카드 뒷면 인쇄 권장)
```
휴대폰 뒷면 윗부분에 카드를 대면 평가·설문 화면이 열립니다.
열리지 않으면: 설정에서 NFC 켜기 (아이폰은 화면만 켜면 됩니다)
그래도 안 되면 주소 직접 입력: <위 4단계 주소>
```
- 아이폰 XS 이상: 화면이 켜져 있으면 자동 인식됩니다.
- 아이폰 7 ~ X: 제어센터에 **NFC 태그 리더**를 추가해 실행해야 합니다.
- 안드로이드: `설정 → 연결 → NFC` 켜기.

# 훈련 당일 운영 절차

1. 교관 휴대폰/PC에서 `https://98brtc-coder.github.io/reserve/admin.html` 접속 → **PIN 로그인**
2. 시작 전에는 **전부 마감** 상태를 유지합니다.
   → 배너가 눌리지 않고, 폼 주소를 직접 알아도 제출이 거부됩니다
3. **과목이 시작될 때마다 그 과목만 엽니다.**
   - 안보교육 시간 → `안보교육` 행의 **[열기]**
   - 끝나면 **[닫기]** → 다음 과목 **[열기]**
   - 3과목을 동시에 진행한다면 **[평가 전체 열기]** 한 번으로 끝납니다
4. 진행 중 현황판으로 관리합니다.
   - **종합 순위**: 과목별 득점률(%) 평균 내림차순, 1위에 🥇 = **우수 조**
   - 한 과목이라도 미제출이 있는 조는 **미완** 표시
   - **과목별 현황** 탭에서 과목을 골라 조별 제출 상태를 봅니다
     · `3-7` 칩이 초록 = 제출 완료, 회색 = 미제출 → 그대로 호명
     · 빨간 칩 `2-10 ?` = 명단에 없는 번호 (번호 오기 의심)
   - **번호 확인 필요** 표: 번호 형식이 틀려 조에 반영되지 않은 응답 (과목명이 함께 표시됩니다)
5. 전 과목 종료 후 **[평가 전체 닫기]** → 그 시점의 종합 순위가 확정됩니다
6. **자동 새로고침 끄기**를 눌러 화면을 고정한 뒤 시상하면 숫자가 중간에 바뀌지 않습니다
7. **CSV 저장** 으로 개인별 점수와 조별 종합 득점률을 내려받아 결과 보고에 사용합니다
8. 설문도 동일하게 **[열기] → [닫기]**. 실시간 결과는 구글폼 `응답 → 요약` 탭에서 확인합니다

> 구글 시트 상단 **`예비군 평가`** 메뉴에서도 전체 열기/닫기와 `종합 순위 보기`가 됩니다.

# 점수 집계 규칙

- **번호 인식**: `3-7`, `3 - 7`, `3조 7번` 모두 인식합니다. 인식 실패 시
  *번호 확인 필요* 목록에 따로 표시됩니다.
- **중복 제출**: 같은 번호가 여러 번 제출하면 **처음 제출만** 인정합니다.
  여러 번 응시해 점수를 올리는 것을 막기 위함입니다. 무시된 제출은 관리자 화면
  **`번호 조회 / 정리 → 중복 제출 목록`** 에 표시됩니다.
- **개인 점수**: 퀴즈형 폼의 `점수` 열을 자동으로 사용합니다. 퀴즈가 아니면
  숫자 문항들을 찾아 `점수계산`(합계/평균)에 따라 계산합니다.
- **조 평균**: 그 조에서 **제출한 인원의 평균**입니다. 미제출자는 0점으로 계산되지
  **않습니다.** 공정한 비교를 위해 **전원 제출을 확인한 뒤 마감**하십시오.
- **종합 순위 (우수 조)**: 과목마다 만점이 달라도 공정하도록 **득점률(%)로 환산한 뒤
  3과목 평균**을 냅니다.

```
              안보교육   전투부상자처치   전시동원절차      종합
              (만점 20)    (만점 10)      (만점 30)
  1조 평균       16           8             24
  → 득점률      80%          80%           80%        →  80.0%
  3조 평균       14           9             27
  → 득점률      70%          90%           90%        →  83.3%  🥇
```

  배점이 큰 과목이 순위를 좌우하지 않습니다. 만점이 3과목 모두 같다면
  총점 합계로 줄을 세운 것과 결과가 동일합니다.

- **만점을 모르는 과목은 종합에서 제외**되고 관리자 화면에 경고가 뜹니다.
  `과목` 탭의 `만점` 칸을 채우면 해결됩니다.

# 문제 해결

| 증상 | 조치 |
|---|---|
| 카드를 태그해도 반응 없음 | NFC 꺼짐 / Mifare Classic 카드 / 금속면 부착 / 태그 위치(아이폰은 상단) 확인 |
| 첫 화면이 "확인 불가" | `config.js` 의 `apiUrl` 오타, 또는 배포 시 **액세스: 모든 사용자** 미설정 |
| 배너가 계속 "준비 중" | 설정 시트의 `평가폼_편집링크` 가 비었거나 `/d/e/` 응시링크가 들어간 경우 |
| 로그인에서 "PIN이 올바르지 않습니다" | 설정 시트 `관리자PIN` 값 확인 (앞뒤 공백 주의) |
| 열기/닫기는 되는데 폼이 안 닫힘 | `평가폼_편집링크` 가 **편집 링크(.../edit)** 인지 확인 |
| 점수가 전부 `-` | 퀴즈 배점 미지정, 또는 `점수열` 을 수동 지정 |
| 조가 안 보임 | `조개수`/`조별인원` 값 확인, 또는 `명단` 탭 확인 |
| "게시되지 않은 양식" 오류 | 해당 폼 편집화면 우측 상단 **`게시`** 버튼을 한 번 누르십시오 |
| "응답 시트를 찾지 못했습니다" | `과목` 탭의 `응답시트` 칸에 실제 시트 이름을 정확히 입력 |
| 종합 순위에서 과목이 빠짐 | `과목` 탭의 `만점` 칸이 비어 있습니다. 숫자를 입력하십시오 |
| 개폐 후 반영이 몇 초 늦음 | 구글폼 쪽 지연입니다. 닫은 뒤 폼 주소를 열어 확인하십시오 |
| 코드를 고친 뒤 반영이 안 됨 | Apps Script 에서 **배포 → 배포 관리 → 연필 → 버전: 새 버전 → 배포** |

# 보안상 알아둘 점

- 관리자 화면은 **PIN 한 개로만** 보호됩니다. 내부망 교육용 수준의 보호이며,
  군사 비밀이나 개인정보를 이 시스템에 넣어서는 안 됩니다.
- 번호(`m-n`)만 수집하므로 성명·군번 등 개인정보는 저장되지 않습니다.
  **평가 폼에 성명·군번 질문을 추가하지 마십시오.**
- 설문은 무기명 원칙을 지키기 위해 폼의 **이메일 수집을 반드시 끄십시오.**
- 페이지 주소를 아는 사람은 누구나 첫 화면을 볼 수 있습니다(검색엔진 노출은
  차단해 두었습니다). 민감 내용은 게시하지 마십시오.
- 응답 스프레드시트는 교관 외에 공유하지 마십시오. PIN이 그 시트에 들어 있습니다.
- 대외 공개·부대 정식 도입 전에는 부대 보안담당자의 검토를 받으십시오.

# 보완 기능 (2026-10 추가)

## 1. 구글 아이디 없이 응시

이미 가능합니다. 비로그인 상태로 확인했고 두 폼 모두 정상 열립니다.
**아래 세 설정을 켜면 로그인이 강제되므로 반드시 끈 상태로 두십시오.**

| 폼 설정 → 응답 | 상태 |
|---|---|
| 이메일 주소 수집 | **끄기** (또는 "응답자 입력") |
| 응답 횟수 1회로 제한 | **끄기** ← 켜면 구글 로그인 강제 |
| 조직 내 사용자로 제한 | **끄기** (기관 계정일 때만 나타남) |

중복 제출은 시스템이 *날짜별·번호별 처음 제출만* 인정하므로 제한을 켤 필요가 없습니다.

## 2. 조별 A안 / B안 (ABBA 반복)

`설정` 시트의 **`안배정`** 값이 패턴입니다. 기본 `ABBA` → 1조부터 반복 적용됩니다.

```
1조 A   2조 B   3조 B   4조 A   5조 A   6조 B   7조 B   8조 A  …
50조까지 → A안 25개 조 / B안 25개 조 (정확히 반반)
```

- 패턴을 `AB` 로 바꾸면 홀수 A / 짝수 B, 비우면 전 조 A안입니다
- **`과목` 시트에 B안 열을 채우면** 그 과목이 A/B로 갈라집니다
  (`B안_폼_편집링크` 만 입력 · 나머지 B안 열은 자동 채움)
- B안 링크가 비어 있으면 그 과목은 **전 조 공통**으로 동작합니다
- A안·B안 응답은 **한 과목으로 합산**되어 조별 평균·종합 순위에 반영됩니다
- 배정과 다른 안으로 제출하면 관리자 화면 **`배정과 다른 안으로 응시`** 표에 표시됩니다

### 카드는 1종만 만드십시오

조별로 카드를 다르게 만들 필요가 **없습니다.** 예비군이 첫 화면에서
**조·번을 한 번 선택**하면 기억되고, 그 뒤로는 자기 안(案)의 폼만 보입니다.

- 조 편성이 바뀌어도 카드를 다시 쓸 필요가 없습니다
- 번호가 폼에 **자동 입력**되므로 번호 오기가 사라집니다
- 조별 카드를 쓰고 싶다면 주소 뒤에 `?g=3` 을 붙여 기록하면 3조가 미리 선택됩니다
  (예: `https://98brtc-coder.github.io/reserve/?g=3`)

## 3. 안보교육 문제 순서 랜덤

**폼에서 설정합니다.** 단, 번호 질문이 섞이지 않도록 섹션을 나누어야 합니다.

1. 첫 번째 섹션: **본인 번호** 질문만
2. `섹션 추가` → 두 번째 섹션에 평가 문항 전부
3. `설정` → **프레젠테이션** → **질문 순서 임의로 섞기** 켜기

섞기는 **섹션 안에서만** 일어나므로 번호 질문은 항상 맨 앞에 남습니다.
보기 순서도 섞으려면 각 문항의 `⋮` → `옵션 순서 임의로 섞기` 를 켜십시오.

> 구글 시트 메뉴 **`예비군 평가 → 문제 순서 섞기 켜기`** 로 등록된 모든 평가 폼에
> 한 번에 적용할 수도 있습니다.

## 4. 조별 평가 개폐 — 가능한 범위와 한계

관리자 화면 **`평가 개폐`** 에 과목별 카드가 있습니다.
**교관은 "열린 조"만 조정하면 되고, 폼 개폐는 자동으로 따라옵니다.**

```
┌ 안보교육  [A/B] ─────────────────────────────────┐
│ 응답 받는 중 · 열린 조 1~10                       │
│ 열 조 [1~10 ] [적용] [전체][없음][A안 조][B안 조]  │
│ [조 선택 펼치기]  → 1~50 격자                     │
└──────────────────────────────────────────────────┘
```

| 열린 조 | 구글폼 응답 수락 | 결과 |
|---|---|---|
| `전체` 또는 `1~10` 등 | **열림** | 열린 조만 화면에서 응시 가능 |
| **`없음`** | **닫힘** | **완전 차단** — 링크를 알아도 제출 불가 |

즉 **완전 마감은 `없음`** 으로 하십시오. 과목을 따로 열고 닫는 버튼은 없습니다.

**`열 조` 칸에 직접 입력**합니다.

| 입력 | 결과 |
|---|---|
| `1,2,7` | 쉼표 — **1조·2조·7조만** 열림 (나머지 닫힘) |
| `1~7` | 물결 — **1조부터 7조까지** 연속으로 열림 |
| `1~5,9` | 섞어 쓰기 — **1~5조와 9조** 가 열림 |
| `전체` | 모든 조 열기 (조별 통제를 쓰지 않을 때) |
| `없음` | 모든 조 닫기 |

버튼으로도 됩니다: `전체` / `없음` / `A안 조` / `B안 조`.
`조 선택 펼치기` 를 누르면 1~50 격자가 나와 조를 하나씩 켜고 끌 수 있습니다.
**설문은 별도 패널**이며 조 구분이 없습니다(무기명).

**⚠ 다만 이것은 "응시 화면에서 링크를 내주지 않는" 통제입니다.**
구글폼은 폼 단위로만 응답을 막을 수 있어, 조 단위 하드 차단은 구조적으로 불가능합니다.

| 상태 | 결과 |
|---|---|
| 과목이 닫힘 | **구글폼이 제출 거부** — 링크를 알아도 못 냅니다 (하드 차단) |
| 과목 열림 + 내 조 닫힘 | 응시 화면에서 **`대기`** 로 막힘. 폼 주소를 직접 알면 제출 가능 |

따라서 **최종 차단은 과목 개폐로, 진행 순서 통제는 조별 개방으로** 쓰십시오.
닫힌 조인데 제출 기록이 있으면 격자에 **금색 테두리**로 표시되니 바로 확인됩니다.

실무 운용 예시:

```
09:00  안보교육 [열기] + 조별개방 1-10      → 1~10조만 응시
09:20  조별개방 11-20                      → 11~20조로 넘김
…
10:00  안보교육 [닫기]                      → 완전 차단, 순위 확정
```


## 5. 번호 선점 (등록 시점에 잠금)

예비군이 첫 화면에서 **조·번을 확정하는 순간 그 번호가 그 날짜에 잠깁니다.**
다른 사람이 같은 번호로 등록하려 하면 이렇게 막힙니다.

```
3-7 은(는) 이미 다른 사람이 등록한 번호입니다.
본인 번호가 맞다면 교관에게 알려 주십시오.
교관이 등록을 풀어 주면 바로 등록할 수 있습니다.
```

- 등록 기록은 스프레드시트 **`등록`** 탭에 쌓입니다 (날짜 · 번호 · 등록시각 · 기기)
- 같은 폰에서 새로고침하거나 다시 태그하면 본인 등록이 그대로 유지됩니다
- 날짜별로 관리되므로 다음 훈련일에는 번호가 다시 비어 있습니다
- 관리자 화면에 **등록 N명 · 등록 후 미제출 M명** 과 미제출 번호 목록이 표시됩니다



번호는 예비군이 **한 번 등록하면 본인이 바꿀 수 없습니다.** 잘못 등록했거나
남이 내 번호로 먼저 제출해 버렸다면 교관이 풀어 줍니다.

**폰에서 번호를 다시 고르게 하려면** — 번호 표시줄 오른쪽 **🔒** 버튼 → 관리자 PIN 입력
→ 번호 재선택 화면이 열립니다. (PIN 을 모르는 예비군은 변경할 수 없습니다)

**번호를 풀어 주려면** — 관리자 화면 **`번호 조회 / 정리`** 에 번호를 적고 **`조회`**

조회하면 등록 여부와 과목별 제출 상태가 나오고, **무엇을 정리할지 골라서** 적용합니다.
**고르지 않은 것은 손대지 않습니다.**

| 고를 항목 | 효과 |
|---|---|
| `번호 등록 해제` | 본인이 다시 등록할 수 있게 합니다. **점수는 그대로 남습니다** |
| 과목별 체크 | 그 과목의 제출 기록만 지웁니다 (A안·B안 함께) |

점수를 지켜야 하는 경우가 대부분입니다. **재접속이 끊긴 사람은 `등록 해제`만**
고르면 이미 받은 점수를 잃지 않고 다시 등록할 수 있습니다. 과목 체크는
그 과목을 잘못 냈을 때만 쓰십시오.

중복 제출이 있으면 **`중복 제출 목록`** 에 번호·횟수가 뜨고, 조별 현황의 칩에도
금색 테두리와 횟수가 표시됩니다.

> **안전장치**: `전체 기간` 조회 중에는 정리가 막힙니다. 과거 기록을 실수로
> 지우는 것을 방지하기 위해 반드시 날짜를 고른 뒤에만 동작합니다.


## 6. 폼 마감 문구에 대해

평가·설문을 닫을 때 시스템이 폼의 "응답을 받지 않을 때 표시할 메시지"도 맞추려 시도합니다.
다만 계정·폼 종류에 따라 이 기능이 지원되지 않는 경우가 있어, **실패해도 조용히 넘깁니다**
(개폐 자체는 정상입니다).

부대 문구를 꼭 띄우고 싶으면 **각 폼에서 한 번 직접 적어 두십시오.** 그 뒤로는 계속 유지됩니다.

```
폼 편집 → 설정 → 응답 → "응답을 받지 않을 때 표시할 메시지"
  → 평가 시간이 아닙니다. 교관 안내에 따라 주십시오.
```


## 7. ⚠ 번호 질문의 "응답 확인(정규식)"은 지우십시오

번호 질문에 응답 확인(정규식)을 걸어 두면 **자동입력된 값이 패턴에 걸려 제출이 막힙니다.**

```
폼에 걸린 정규식 : ^\d{1,2}-\d{1,2}-[A-Za-z0-9]{4}$   ← 3-7-AB12 형태를 요구
시스템이 넣는 값 : 3-7                                  → "패턴이 일치해야 합니다"
```

**조치** — 6개 폼(3과목 × A·B) 모두에서

1. 번호 질문 우측 하단 **`⋮` → `응답 확인`** 체크 해제
2. **`필수` 는 그대로 두십시오** (빈칸 제출 방지)

**번호 질문 자체는 지우면 안 됩니다.** 응답 시트의 번호 열이 조별 집계의 유일한 근거입니다.

## 8. `등록` 시트의 자동 날짜 변환

구글 시트는 `1-10` 을 **1월 10일**로, `2026-10-17` 을 날짜로 바꿔 저장합니다.
이 때문에 등록 조회·중복 차단·초기화가 모두 실패할 수 있어 두 겹으로 막아 두었습니다.

- `등록` 시트의 `날짜`·`번호` 열을 **텍스트 서식**으로 고정
- 읽을 때는 `조`·`번` 숫자 열에서 번호를 되살리고, 날짜는 Date/문자열 양쪽을 모두 처리

**`등록` 시트의 열 서식을 임의로 바꾸지 마십시오.**

## 9. 등록을 풀면 폰도 번호를 놓습니다

폰은 고른 번호를 자기 저장공간에 기억합니다. 그래서 **접속할 때마다 서버에
"아직 내 번호인가"를 다시 묻습니다.** 교관이 등록을 풀었는데 폰만 모르고
그 번호로 계속 응시하는 일을 막기 위한 것입니다.

| 서버 답 | 폰 동작 |
|---|---|
| 아직 본인 것 | 그대로 둡니다 |
| 등록이 풀렸다 | 번호를 놓고 **조·번 선택 화면** + *"교관이 3-7 등록을 풀었습니다"* |
| 다른 사람이 등록했다 | 번호를 놓고 **조·번 선택 화면** + *"다른 사람이 등록한 번호가 되었습니다"* |
| 어제 번호다 | **말없이** 번호를 놓고 조·번 선택 화면 |
| 답이 없다 (통신 실패) | **아무 것도 지우지 않습니다** |

마지막 줄이 중요합니다. 서버가 잠깐 막혔다고 응시 중인 수백 명의 번호가
날아가면 안 되므로, **확실히 아닐 때만** 놓습니다.

- 이 확인은 화면 상태 조회와 **나란히** 보내므로 접속이 느려지지 않습니다
- 읽기만 하므로 이 확인 때문에 등록이 되살아나지 않습니다
- 교관이 등록을 푼 즉시 반영됩니다 (캐시가 막지 않습니다)
- 같은 사람이 날마다 다른 조·번으로 들어와도 됩니다 — 등록은 **하루 단위**입니다

> 카드 주소에 `?g=3&n=7` 처럼 번호를 박아 둔 경우는 서버 등록을 거치지 않으므로
> 이 확인을 하지 않습니다.

# 문제가 생겼을 때 — 먼저 `진단`

구글 시트 메뉴 **`예비군 평가` → `진단 (상태 찍어보기)`**

시트 ID · 시간대 · 설정값 · 설정 시트 원본 행 · 트리거 · 설문 폼 상태가 한 화면에 나옵니다.
바깥에서 추측하는 것보다 이 결과 하나가 훨씬 빠릅니다.

```
[환경]
시트 이름 : 26년 예비군 안보교육 평가문제지(A안)(응답)
시간대    : Asia/Seoul
오늘      : 2026-10-18

[설정 값]
설문개방 = [아니오]
개방기준일 = [2026-10-18]
개방기준일(해석) = [2026-10-18]   ← 오늘과 같아야 정상

[설문 폼]
응답 수락 : false
게시 여부 : true
```

## 꼭 알아둘 함정 3가지

### ① 구글 시트는 날짜처럼 생긴 값을 날짜로 바꿔 저장합니다

`2026-10-18` → 내부적으로 `Date` 객체가 되어 문자열 비교가 영원히 어긋납니다.
`1-10` 은 **1월 10일**이 됩니다.

실제로 이것 때문에 **설문이 열자마자 다시 닫히는** 일이 있었습니다.
`등록` 시트의 `날짜`·`번호` 열, `설정` 시트의 `개방기준일`·`마지막자동마감` 은
**텍스트 서식으로 고정**해 두었고, 읽을 때도 Date/문자열 양쪽을 처리합니다.

> **그 칸들의 서식을 임의로 바꾸지 마십시오.**

### ② 메뉴·트리거와 화면은 서로 다른 코드로 돕니다

```
시트 메뉴 · 자동마감 트리거  →  편집기에 저장된 최신 코드
예비군 화면 · 관리자 화면     →  "배포된" 코드
```

코드를 고친 뒤 **저장만 하고 재배포를 안 하면** 메뉴는 새 코드, 화면은 옛 코드로 돌아
상태가 서로 어긋납니다. 화면 동작이 이상하면 **재배포부터** 확인하십시오.

```
배포 → 배포 관리 → 연필 ✏️ → 버전: 새 버전 → 배포
```

### ③ 닫힌 폼은 바깥에서 점검할 수 없습니다

닫힌 구글폼은 입력칸이 없는 안내 페이지만 내보냅니다.
자동입력이나 문항 구성을 확인하려면 **그 과목을 잠깐 열고** 봐야 합니다.

## 설정 값이 깨졌을 때 복구

`설정` 시트의 **`값` 칸(B열)만** 수정하십시오. **`항목` 칸(A열)은 건드리지 마십시오.**

값이 이상해졌으면:

1. 그 **행을 통째로 삭제** (행 번호 우클릭 → 행 삭제)
2. 메뉴 **`예비군 평가` → `설정 / 과목 시트 준비`** 실행
   → 빠진 항목만 올바른 기본값으로 다시 추가됩니다 (다른 값은 안 건드림)

`과목` 시트의 열이 빠졌을 때도 같은 방법입니다.

## 그 밖의 점검 메뉴

| 메뉴 | 쓸 때 |
|---|---|
| `자동입력 점검 / 복구` | 폼의 번호 질문을 고친 뒤 (entry 아이디가 바뀜) |
| `응답 시트 다시 찾기` | 응답 탭 이름을 바꾼 뒤 |
| `링크 캐시 비우기` | 응시링크·자동입력링크를 새로 만들고 싶을 때 |
| `지금 전부 마감` | 훈련이 끝났을 때 (습관적으로 눌러 두십시오) |
